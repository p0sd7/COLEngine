

# COLEngine

Учебный движок двумерной физики на C++ и SFML. Проект сравнивает три способа симуляции столкновений: дискретный, непрерывный (CCD) и многочастотный (MultiRate).

Объекты представлены прямоугольниками AABB без вращения. Поддерживаются столкновения динамических тел со статическими препятствиями и друг с другом, включая взаимодействие обычных и быстрых объектов.

Видео демонстрации работы: https://drive.google.com/file/d/1B09hO2NJ5OUH8ZR6UF7IIjcc1miaek54/view?usp=sharing

## Возможности

- Переключение алгоритма симуляции во время работы.
- Четыре демонстрационные сцены.
- Пауза, перезапуск сцены и выполнение одного физического шага.
- Изменение параметров через `config.ini` без перекомпиляции.
- Проверка повторяемости симуляции.
- Бенчмарк физического ядра.
- Запись статистики работающего приложения в CSV.

## Зависимости и сборка

- C++17.
- CMake 3.28 или новее.
- Git.
- SFML 3.0.2 — загружается через CMake FetchContent.
- Компилятор с поддержкой C++17.

Проект разрабатывался в Windows с использованием Visual Studio. Для первой конфигурации требуется доступ к интернету для загрузки SFML.

### Visual Studio

1. Клонировать репозиторий:

   ```bash
   git clone https://github.com/p0sd7/COLEngine.git
   ```

2. Открыть папку проекта в Visual Studio.
3. Дождаться завершения конфигурации CMake.
4. Выбрать конфигурацию `x64 Debug` или `x64 Release`.
5. Выбрать `mechanics_lab.exe` как цель запуска.
6. Собрать и запустить проект.

Для измерения производительности использовать **x64 Release**, желательно без подключённого отладчика.

### Командная строка

Пример для генератора Visual Studio:

```bash
cmake -S . -B build -A x64
cmake --build build --config Release --target mechanics_lab
```

При стандартном расположении результатов сборки:

```powershell
.\build\Release\mechanics_lab.exe
```

## Управление

| Клавиша | Действие |
|---|---|
| `1` | Дискретный режим |
| `2` | Режим CCD |
| `3` | Режим MultiRate |
| `F1` | Сцена с тонкой стеной |
| `F2` | Сцена с двумя стенами |
| `F3` | Стопка блоков |
| `F4` | Смешанная система объектов |
| `Space` | Пауза / продолжение |
| `N` | Один физический шаг на паузе |
| `R` | Перезапуск текущей сцены |
| `F5` | Перечитать `config.ini` и пересоздать сцену |
| `F6` | Проверить повторяемость текущей сцены и режима |
| `F7` | Запустить бенчмарк сцен и режимов |

Клавиши обрабатываются, когда окно приложения находится в фокусе. Например, `F5` в Visual Studio запускает отладку, а `F5` в окне COLEngine перечитывает конфигурацию.

## Режимы симуляции

### Discrete

Все динамические тела обновляются с основной частотой, по умолчанию 60 Гц. После перемещения выполняются поиск пересечений и итерационное разрешение контактов.

Быстрое тело может полностью пересечь тонкую стену между двумя проверками. Поэтому данный режим используется в том числе для демонстрации туннелирования.

### CCD

Используется Swept AABB: по относительной скорости тел вычисляется момент первого контакта внутри физического шага.

Система продвигается до найденного контакта, обрабатывает столкновение и продолжает оставшуюся часть шага. За один шаг могут обрабатываться несколько последовательных столкновений.

Количество событий ограничено параметром `max_ccd_events`. Достижение лимита и отброшенное время симуляции учитываются в статистике.

### MultiRate

Обычные тела обновляются с основной частотой, быстрые — с повышенной. При настройках 60/240 Гц на один основной шаг приходится четыре быстрых подшага.

Для столкновений между группами состояния обычных объектов прогнозируются на момент быстрого подшага. Столкновение изменяет скорости обоих участников, после чего дальнейшее движение учитывает эти изменения.

Меньший шаг снижает вероятность туннелирования, но не исключает его при произвольно больших скоростях.

## Демонстрационные сцены

| Сцена | Что проверяется |
|---|---|
| `F1 — Wall` | Пролёт быстрого тела через тонкую стену |
| `F2 — MultipleBounces` | Последовательные столкновения между двумя стенами |
| `F3 — Stack` | Столкновения динамических тел и устойчивость стопки |
| `F4 — System` | Совместная работа обычных тел, быстрых тел и препятствий |

При стандартной конфигурации `F4` содержит 20 обычных динамических тел, 2 быстрых тела, 5 препятствий и пол.

Для сцен `F1` и `F2` гравитация отключена. В `F3` и `F4` используется `gravity_y` из конфигурации.

## Конфигурация

Параметры задаются в `config.ini` в формате `ключ=значение`. Строки с `#` являются комментариями.

После изменения файла нужно сохранить его и нажать `F5` в окне приложения. Сцена пересоздаётся, накопленное время сбрасывается. При ошибке загрузки сохраняются предыдущие настройки.

Пример конфигурации:

```ini
# Frequencies
physics_hz=60
fast_physics_hz=240

# Motion
restitution=1
projectile_speed=2000
gravity_y=980

# Contact solver
solver_iterations=12
penetration_slop=0.01
position_correction=0.8
restitution_threshold=60

# CCD
ccd_solver_iterations=48
max_ccd_events=64
contact_distance=0.02
closing_speed_epsilon=0.01

# Scenes
wall_thickness=10
stack_count=5
system_regular_count=20
system_fast_count=2
system_obstacle_count=5
system_regular_half_size=10
system_fast_half_size=4

# Application
max_frame_time=0.25
```

Основные параметры:

| Параметр | Назначение |
|---|---|
| `physics_hz` | Основная частота физики |
| `fast_physics_hz` | Частота быстрых объектов в MultiRate |
| `restitution` | Коэффициент восстановления: от 0 до 1 |
| `projectile_speed` | Начальная скорость быстрых тел |
| `gravity_y` | Ускорение свободного падения по вертикали |
| `solver_iterations` | Число итераций обычного решателя контактов |
| `restitution_threshold` | Порог скорости, ниже которого отскок подавляется |
| `ccd_solver_iterations` | Число итераций решателя контактов CCD |
| `max_ccd_events` | Максимальное количество событий CCD за шаг |
| `contact_distance` | Допуск расстояния для формирования контакта |
| `closing_speed_epsilon` | Допуск при проверке скорости сближения |
| `max_frame_time` | Максимальное время кадра, принимаемое аккумулятором |

Частота быстрых объектов должна быть не меньше основной и делиться на неё без остатка.

Координаты и размеры заданы в пикселях, время — в секундах. Ось Y направлена вниз. Параметры `half_size` задают половину размера тела.

При `restitution=1` сильные столкновения моделируются как упругие. Однако для слабых столкновений действует `restitution_threshold`, поэтому такое значение не означает полного отсутствия потерь энергии во всей симуляции.

Путь к конфигурации задаётся при сборке через CMake. Копирование только исполняемого файла не создаёт самостоятельную переносимую версию приложения.

## Архитектура

Физическое ядро отделено от SFML и не использует графические типы библиотеки.

| Компонент | Ответственность |
|---|---|
| `Application` | Главный цикл, команды, переключение режимов, управление временем |
| `SfmlFrontend` | Окно, ввод и отрисовка |
| `PhysicsWorld` | Хранение тел и выполнение физических шагов |
| `Collision` | Проверки AABB, поиск контактов и времени столкновения |
| `Body`, `Math`, `PhysicsSettings` | Физические данные, векторные операции и настройки |
| `SceneFactory` | Создание демонстрационных сцен |
| `Config` | Загрузка и проверка параметров конфигурации |

Отрисовка и физика используют независимые частоты. Физика выполняется с фиксированным шагом через аккумулятор времени.

## Проверка повторяемости

Клавиша `F6` запускает два независимых прогона текущей сцены и режима с одинаковыми начальными условиями.

Состояния сравниваются после каждого физического шага. Результат выводится в консоль:

```text
PASS: states match at every step.
```

Проверка подтверждает повторяемость в рамках текущей сборки и окружения. Она не гарантирует побитового совпадения между разными платформами или компиляторами и сама по себе не доказывает физическую корректность алгоритма.

## Измерение производительности

### Бенчмарк физического ядра — F7

Выполняются прогоны всех сцен во всех режимах. Измеряется время выполнения физики без отрисовки.

Результаты сохраняются в:

```text
results/benchmark_<timestamp>.csv
results/benchmark_<timestamp>_settings.txt
```

Файл настроек позволяет воспроизвести условия измерения.

### Статистика работающего приложения — F8

Первое нажатие запускает запись с начала текущей сцены, повторное — завершает её.

Результаты сохраняются в:

```text
results/frames_<timestamp>.csv
```

Каждая строка содержит статистику за интервал записи, включая количество кадров, физических шагов, быстрых подшагов и событий CCD.

| Показатель | Значение |
|---|---|
| `physics_ms` | Суммарное время вычисления физики |
| `ms_per_frame` | Время физики, делённое на количество кадров отрисовки |
| `ms_per_step` | Время физики, делённое на количество основных физических шагов |
| `fast_steps_per_frame` | Среднее количество быстрых подшагов на кадр отрисовки |
| `ccd_events` | Количество обработанных событий CCD за интервал |
| `ccd_limit_hits` | Количество достижений лимита событий CCD |
| `ccd_discarded_ms` | Отброшенное время симуляции при достижении лимита |

`ms_per_frame` характеризует затраты на физику и не является полной длительностью кадра приложения.

При частотах 60/240 Гц выполняются четыре быстрых подшага на основной физический шаг. На кадр отрисовки их может приходиться меньше: например, при 144 FPS среднее составляет около 1,67.

Для объединения нескольких интервалов используются суммы:

```text
ms/frame = sum(physics_ms) / sum(frames)
ms/step  = sum(physics_ms) / sum(physics_steps)
```

## Пример результатов

Измерения сцены `System` в Release при 60/240 Гц, `restitution=1`, 20 обычных и 2 быстрых телах:

| Режим | Физика, мс/кадр | Физика, мс/шаг |
|---|---:|---:|
| Discrete | 0,01344 | 0,03230 |
| CCD | 0,03450 | 0,08287 |
| MultiRate | 0,02320 | 0,05573 |

Значения рассчитаны по суммарному времени физики и суммарным счётчикам записанных интервалов. В этих прогонах достижения лимита CCD и отброшенного времени не зафиксированы.

Результаты зависят от оборудования, сборки, сцены и нагрузки системы. Для сравнения на другом компьютере следует повторить измерения.

## Ограничения

- Используются только прямоугольники AABB без вращения.
- Угловая динамика и трение не моделируются.
- Discrete и MultiRate допускают туннелирование при достаточно большом перемещении за шаг.
- CCD имеет конечный лимит событий.
- Синхронизация групп в MultiRate является приближением и может давать отличия при цепочках столкновений.
- Устойчивость стопки зависит от шага времени, коэффициента восстановления и параметров решателя.
- Геометрия демонстрационных сцен рассчитана на стандартные настройки; увеличение числа тел может потребовать изменения их начального размещения.
